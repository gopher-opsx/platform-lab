# Code of Conduct

## Our Commitment

Platform Lab is an open-source learning project.

We want participation in the project to be professional, constructive, respectful, and welcoming to people with different backgrounds and levels of experience.

Students, contributors, maintainers, and community members should be able to participate without harassment or unnecessary hostility.

## Expected Behavior

Examples of positive behavior include:

- being respectful and professional
- giving constructive technical feedback
- helping less-experienced contributors understand problems
- accepting reasonable technical disagreement
- focusing criticism on code, design, documentation, or behavior rather than individuals
- acknowledging mistakes and correcting them
- respecting different levels of experience
- keeping discussions relevant to the project
- helping maintain a useful learning environment

Technical disagreement is normal and welcome.

Disagreement should remain focused on improving the project.

## Unacceptable Behavior

The following behavior is not acceptable:

- harassment
- personal attacks
- insults or degrading comments
- discriminatory language or behavior
- threats or intimidation
- deliberate disruption of project discussions
- publishing another person's private information without permission
- repeated unwanted contact
- spam or unrelated promotion
- knowingly submitting malicious code
- intentionally introducing harmful behavior into training scenarios
- attempting to access systems or information unrelated to Platform Lab

## Technical Discussions

Platform Lab is an engineering and training project.

Code reviews and technical discussions may involve strong opinions about:

- architecture
- implementation
- security
- reliability
- Docker
- networking
- distributed systems
- troubleshooting methods
- documentation
- course compatibility

Challenge the idea, implementation, or evidence—not the person.

Whenever possible, technical arguments should be supported by:

- reproducible behavior
- logs
- tests
- documentation
- measurements
- code
- clear reasoning

This reflects the same evidence-based troubleshooting philosophy used throughout Platform Lab.

## Student and Beginner Questions

Platform Lab is also intended for learners.

Questions that appear basic to an experienced engineer may be important to someone learning containers or platform engineering for the first time.

Community members should avoid dismissive responses such as:

```text
This is obvious.
Just Google it.
You should already know this.
```

Instead, point people toward the relevant documentation, command, evidence, or concept whenever practical.

## Maintainer Responsibilities

Project maintainers are responsible for interpreting and enforcing this Code of Conduct.

Maintainers may:

- edit or remove inappropriate comments
- close disruptive discussions
- reject contributions that violate project expectations
- temporarily restrict participation
- permanently restrict participation in serious or repeated cases

Enforcement decisions should be based on the behavior involved and its impact on the project or community.

## Scope

This Code of Conduct applies to participation in official Platform Lab project spaces, including:

- repository issues
- pull requests
- code reviews
- discussions
- documentation contributions
- project communication channels

It may also apply when someone publicly represents the Platform Lab project.

## Reporting Problems

If you experience or observe behavior that violates this Code of Conduct, report it to the project maintainer.

For ordinary project disagreements, use the relevant issue or pull-request discussion.

For serious harassment, threats, privacy violations, or sensitive matters, avoid posting personal or sensitive details publicly.

Use a private communication or reporting mechanism when one is available.

Reports should include enough information to understand:

- what happened
- where it happened
- who was involved
- any relevant links or screenshots
- whether the behavior is ongoing

Reports should be reviewed fairly and with appropriate respect for privacy.

## Enforcement Guidelines

Depending on severity and context, possible responses include:

### 1. Correction

For minor or accidental inappropriate behavior, the contributor may be asked to correct the behavior or edit the content.

### 2. Warning

For more significant or repeated behavior, a formal warning may be issued.

### 3. Temporary Restriction

Participation may be temporarily restricted when behavior repeatedly disrupts the project or community.

### 4. Permanent Restriction

Serious harassment, threats, malicious activity, repeated violations, or deliberate harm to the community may result in permanent restriction from official project spaces.

## Good Faith

Mistakes happen.

A contributor who receives constructive feedback and makes a reasonable effort to correct their behavior should normally be allowed to continue participating.

The purpose of this policy is to protect productive collaboration—not to punish ordinary disagreement or honest mistakes.

## Project Principle

Platform Lab teaches engineers to investigate systems using evidence before drawing conclusions.

The same principle should apply to collaboration:

```text
understand context
      ↓
collect evidence
      ↓
discuss the problem
      ↓
improve the system
```

Respectful engineering produces better software and a better learning environment.
